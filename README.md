# 人气榜选股系统 · 本地部署包

一套纯免费数据源的人气榜选股系统：同花顺热榜 → 东财 F10 概念 → 腾讯行情 → 概念分类/动量 → 评分排序 → 静态 HTML 页面。

## 文件说明

| 文件 | 作用 |
|---|---|
| `update_data.py` | 主程序：抓数据 → 算概念 → 评分 → 输出 `data.json` |
| `free_data.py` | 免费数据层（热榜/行情/K线/概念/新闻/板块强度），无第三方依赖 |
| `loop.sh` | 定时器：每交易日 9:00 / 10:00 / 13:00 各跑一次 |
| `history.json` | 10 日历史快照，用于算概念增量、板块动量、10 日综合指数 |
| `index.html` | 展示页面（内嵌一份快照，无数据时不会白屏） |
| `data.json` | 最新一次运行结果 |
| `score_stock.py` | 单只股票评分明细查询（调试用） |
| `call.py` | 旧版 iFinD 调用脚本（**已停用**，额度耗尽，保留仅供参考） |

## 环境要求

- Python 3.8+（本机 `python3` 即可）
- 只需 `requests`：`pip install requests`
- 能访问 `qt.gtimg.cn`、`quotes.sina.cn`、`emweb.securities.eastmoney.com`、`eq.10jqka.com.cn`、`www.55188.com`

## 三步跑起来

```bash
# 1. 装依赖
pip install requests

# 2. 先手动跑一次，确认能出数（约 1-2 分钟，取决于股票池大小）
python3 update_data.py
# 成功会生成/更新同目录下的 data.json

# 3. 起定时器（每交易日 9:00/10:00/13:00 自动跑）
nohup bash loop.sh > /dev/null 2>&1 &
```

> `loop.sh` 里写的是相对路径 `cd $(dirname $0)`，放在哪个目录都能跑。若你的 Python 命令不是 `python3.11`，把 `loop.sh` 里的 `python3.11` 改成 `python3`。

## 看页面

**方式 A（最简单）**：直接双击 `index.html`。页面内嵌了最后一次的快照数据，能看，但不会自动更新（浏览器安全策略不允许 `file://` 下读 `data.json`）。

**方式 B（推荐，能自动刷新）**：在包目录起个静态服务，浏览器开 `http://localhost:8000/index.html`

```bash
python3 -m http.server 8000
```

页面每 60 秒自动重新拉一次 `data.json`，定时器跑完后页面自己就更新了。

**表头点击排序**：三张表的表头都能点，三态 —— 第一次降序 ▼、再点升序 ▲、第三次回到默认顺序（评分榜的默认 = 服务端排好的「10 元以下优先 + 分数」）。缺值（`--`）永远沉底，不随升降序翻转；表头有箭头才表示当前在按该列排。「#」序号列与「轨迹」列不参与排序。

**改成自己的端口/路径**：编辑 HTML 末尾的 `fetch("data.json?t="+Date.now())`，把 `data.json` 换成你的实际 URL 也行（比如放到内网服务器上）。

## 评分公式（方便你改参数）

```
score_final = min(100, composite × pf × posf × board_bonus × lhb_factor × mv_factor)
composite   = 100 × √(L × M) × concept_factor × t_factor
L = 1 − log10(排名) / log10(5580)           # 人气排名水平分：第1名=1.0、第10名≈0.73、第100名≈0.46
M = clamp(热度增速/100, 0, 1)               # 增速 = 跨日(vs前5日均排名) + 0.4×日内加速
board_bonus = 连板高度：首板1.02 / 2板1.05 / 3板1.07 / 4板1.09 / 5板1.11 / ≥6板1.12
lhb_factor  = 龙虎榜：机构席位净买1.03；机构净卖且收跌0.98；其余净买1.01
mv_factor   = 流通市值软约束：≥1500亿×0.85、≥500亿×0.92、其余1.00（低价妖股出自小盘）
pf = 价格因子：2~10 元 1.03→1.18（低价妖股区，越便宜加越多）
                10~20 元 1.00→1.03（只做可介入性微调）
                ≥20 元 1.00（贵不等于差，不罚）  <2 元 1.10（面值退市风险，封顶）
posf = 位置因子：股价在近 60 日高低区间的相对位置 ≤35% → 1.08、35~65% → 1.04、>65% → 1.00
concept_factor = 基础分(龙头1.0/前3名0.9/其他0.68) × 梯队因子 × 板块动量因子 × 题材催化
t_factor = 换手因子（低位启动 ×1.07 / 首启放量 ×1.08 / 均线粘合 ×1.05，可叠加）
```

权重次序（谁说得上话）：**√(L×M) 是主项**（0~100 分全部来自它），其次是概念系数（0.68~1.0）和换手因子（1.0~1.21）；
价格因子最高 +18% 但**只对 10 元以下生效**，位置因子最高 +8%，连板最高 +12%、机构净买 +3%；
所有乘性加成之后再 `min(100, …)` 封顶。


**L 为什么是对数**：池子本身就是"今天的热榜前 100"，用 `1 − 排名/5580` 的话池内每一只都 ≈0.98，
对排序毫无区分度。对数标尺才能把第 10 名（0.73）和第 120 名（0.43）拉开，也让"全市场人气第一"
拿到接近满分的 L，而不是被前 15 名折扣压到 0.07。

**热度增长为什么不用同花顺的 `hot_rank_chg`**：该字段在盘后**整批返回 0**（实测 100/100 全为 0），
用它算增长会让 84% 的股票增长=0、整张榜清零。现在改用东财 `stockrank/getHisList`
的逐日人气排名（120 天，今日那条盘中实时更新），基数取前 5 个交易日均值。

**日内加速（2026-10-29 加）**：同花顺热榜有 `hour`（近一小时）和 `day`（当日）两个榜，
两榜名次差 `(day名次 − hour名次)/day名次` 就是"最近一小时在不在被抢"——这是收盘后唯一还活着的
当日动能字段（`hot_rank_chg` 那时已经全 0）。实测顺灏股份 day#94 → hour#36 = +62.8%，
拉萨/首板小票普遍在这一项上露头。

⚠ **加速只能做正向加成、不能与跨日取加权平均**：day 榜第 1 名的加速上限天然是 0（它已经在第一），
第 94 名却能轻松算出 +60%。0.65/0.35 平均的结果是把跨日高增长的头部票系统性压低
（实测文投控股 跨日 97.5 + 加速 9.4 被平成一个 66.7，直接掉出前三）。所以是 `增长 = 跨日 + 0.4×max(0, 加速)`。

**55188 的三个接口**（`sec.php?action=`）：
- `blocks` 板块强度榜（强度/涨幅/主力净额）—— ⚠ 只在**盘中**更新（实测 `at` 停在 13:13），盘后评分不用它，只做展示。
- `fry_themes` 明日主题：每个题材带一句催化剂新闻 + 当日涨停家数 + 是否新题材，进 `concept_factor`（涨停≥3家 +5%、新题材 +3%）。
- `lhb_board` 龙虎榜：带 `org_net`（机构席位净买）和 `topics`（概念标签），既做资金验证，也补概念归属。

**股票池 = 东财人气榜前 100 ∪ 同花顺 hour 前 100 ∪ 同花顺 day 前 100**（实测并集约 150 只）。只用同花顺会漏掉
"东财热、同花顺冷"的票（如 601188 东财 41 名、同花顺前 100 之外）；只用东财又拿不到概念标签和连板高度。
排名一律按东财全市场口径，才能和 5580 的名次刻度对齐。

**概念归属 = 同花顺 concept_tag ∪ 55188 龙虎榜 topics ∪ 东财 F10**，三个源都过同一道泛词闸，
顺序上把同花顺/龙虎榜的标签放前面（那是"当下在炒的标签"），东财 F10 放后面兜底。
没进热门集群的票也会回填它自己的第一个标签，概念列不留空（但系数保持 1.0，集群加持只给真抱团的票）。

**榜单口径**：先按「10 元以下 / 10~20 元」分桶，桶内再按分数排 —— 所以低价票只要够，榜单就被低价票占满；
低价票不够 10 只时才由 10~20 元的补位（不是硬截断，不会凑不满）。

参数都在 `update_data.py` 顶部：`PF_MAX_BONUS` / `PF_BASE_BONUS` / `PF_SWEET_PRICE` / `PF_CAP_PRICE` /
`PF_FLOOR_PRICE` / `POS_BONUS` / `POS_WINDOW` / `MAX_PRICE`（准入价，与加分无关）。

改了这三个参数、概念基础分或动量系数后，重跑一次即可。

## 概念过滤的三道闸（这是这套系统的核心）

1. **泛词闸**（2026-10-29，用户令「『百日新高』是个泛词，这类词不属于概念」→「过滤泛词」）：六类一律剔除 —— ①行业名（`_INDUSTRY` 词表，东财一级+二级）②地域 ③指数成分/交易属性（融资融券、昨日涨停、破净、参股、重仓/新进/增减持）④技术形态词（百日新高、近期新低、连续上涨、均线多头、趋势股、昨日首板）⑤财报事件（三季报增长、中报预增）⑥风格标签（科技风格、大盘成长）。
   - 实现 = `free_data.is_generic_concept()`，**四个入口全走同一个判据**：F10 抓取 `filter_concepts`、集群统计 `add_concept_stats`、新闻归因 `fetch_reasons`、板块强度 `fetch_55188_blocks`（这个源返回全谱板块，原来不过闸，「银行」「三季报增长」就这样顶到强度榜首）。
   - 判据按**词形**优先（`_GENERIC_PAT`），词表只做补丁（`_INDUSTRY` / `_GENERIC_WORDS` / `_STATIC_EXCLUDE`），另有 `_KEEP` 白名单挡住误伤（白酒、酿酒概念、中药概念、快递概念、预制菜概念…）。
   - ⚠ 上游 `BOARD_NAME` 常带**尾随空格**（`"百日新高 "`），精确匹配的黑名单会被这样静默绕过 —— 所以入闸前先 `norm_concept()` 归一化（去不可见字符/全角空格、折叠空白、去首尾），归一化后的名字同时用于分组，避免同一概念被拆成两个组。
   - 体检工具：`python _audit_concepts.py` —— 把当前股票池所有原始板块名拉一遍，逐个标「通过/被哪条拦下」，产出 `_concept_audit.json`。2026-10-29 实测：原始 522 个 → 拦截 292 / 通过 230。
2. **新闻催化验证**：龙头股近期资讯里，催化词必须出现在概念名 40 字以内，否则视为伪概念（解决"挂着比亚迪概念实际走机器人"的问题）。
3. **影子概念合并**：某概念 ≥75% 的成员被一个更大的概念覆盖时，剔除小的那个。

## 每日维护

- `history.json` 只保留最近 10 个交易日，程序自动裁剪，不用手动清。
- `loop.log` 会慢慢变大，定期 `tail -100 loop.log` 看有没有报错即可。
- 交易日判断在 `loop.sh`（周一到周五），法定节假日它会照跑但数据基本不动，不影响。

## 常见问题

**Q：`data.json` 里 leaderboard 是空的？**
A：全市场当天没有正分股。查看 `fallback` 字段（相对分前 5），页面会自动降级显示。

**Q：概念表里的板块动量一直是 0？**
A：板块动量依赖前一日快照做差。第一天跑必然是 0，第二天起才有值。

**Q：跑得很慢？**
A：慢在逐个拉 F10 概念和个股新闻（100 只股票 × 2 个请求）。可以把 `fetch_concepts` 的 `TOP_N` 调小，或只在 13:00 那次跑全量。
